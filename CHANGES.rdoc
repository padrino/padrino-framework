== Unreleased

- FIX #2429 Generators print only the message and exit 1 for an invalid name (`padrino g controller 1abc`, `g model 2bad`, `g app 4y`, `g project 9bad`, a name with `/` for controller, helper, mailer, migration or task), as they do for other usage errors since #2411, instead of a NameError backtrace. Custom generators that call `valid_constant?`, `validate_namespace` or `already_exists?` from `Padrino::Generators::Actions` now get a `Thor::Error` there instead of a `NameError`, and Ruby code that calls a generator's `start` with an invalid name gets a `SystemExit` with status 1 (@nesquena)
- FIX #2428 padrino-admin's `pat`, `mat` and `mt` helpers and project module names (`human_name`) work without ActiveSupport: they called `String#humanize`, which only exists when ActiveSupport is loaded (generated admin apps require it), so an app using `Padrino::Admin::AccessControl` or the admin helpers without it raised NoMethodError. Access control also looked up the admin model with `String#constantize`, so without padrino-gen or ActiveSupport loaded it reported "You must define an Account Model" even when the model existed. These now use `Padrino::Inflections`, which still defers to ActiveSupport when it is loaded (@nesquena)
- FIX #2428 The admin list page's actions menu in erb and slim projects gets the classes the admin stylesheet and script use, as haml projects already did: erb wrote `list-menu-wrapper.list-menu-wrapper-disabled` as one class on the Deselect all and Delete selected items, and slim wrote `list-menu-toggle.dropdown-toggle` on the menu button. Slim's menu also gets `role="menu"` instead of the invalid `role="dropdown"`. Only newly generated admin pages change; edit `admin/views/<page>/index.{erb,slim}` to fix existing ones (@nesquena)
- FIX #2427 `require_dependencies` (and `insert_into_gemfile`) in plugins and templates adds gems in a group other than `:test`, such as `group: :development`, to the Gemfile. It looked for a `# Development requirements` section that generated Gemfiles don't have, so it silently added nothing; the gem now goes under `# Component requirements` with its `group:` option. An Array group (`group: [:development, :test]`) is written as an Array, and with several gems and a `version:`, every gem gets the version, not only the last (@nesquena)
- NEW #2426 `padrino g model` and `padrino g migration` read field modifiers in any order after the kind. With ActiveRecord and Sequel, `index`, `uniq` and `polymorphic` combine: `owner:belongs_to:polymorphic:uniq` makes a polymorphic reference with a unique index, and `uniq` wins over `index` (`email:string:index:uniq` gets one unique index). Mongoid recognizes `polymorphic` in any position; it still ignores `index` and `uniq`. A modifier in fourth or later position now counts (@achiurizo)
- NEW #2425 Projects and apps generated with `padrino g project`, `padrino g app` and `padrino g admin` set `secure: Padrino.env == :production` on the session cookie, so production sends it over HTTPS only. Over plain HTTP, production then sends no session cookie and logins and form posts fail; behind a TLS-terminating proxy, have the proxy send `X-Forwarded-Proto: https`, or set `secure: false`. Existing apps are unchanged. To opt in, use `set :sessions, same_site: :lax, secure: Padrino.env == :production` in every app of the project (it replaces `enable :sessions` in projects generated before 0.17.0). The apps share one session cookie, so an app without the setting rewrites it without Secure; that includes an app added to an existing project with `padrino g app` or `padrino g admin` (@achiurizo)
- FIX #2424 `-d sequel` projects: `rake sq:migrate` (`db:migrate`), `sq:migrate:down`, `sq:migrate:auto` and `sq:reset` succeed when there are no migrations yet, as `ar:migrate` does, instead of failing with `Sequel::Migrator::Error`. A new project has none, and neither does a clone of one, since git drops the empty `db/migrate` (@nesquena)
- FIX #2423 `-t bacon` projects: `rake test` exits non-zero when a spec fails or errors, and prints Bacon's summary. It used to exit 0, so CI passed with failing specs. In an existing project, add `Bacon.summary_on_exit` to `test/test_config.rb` after the `require_relative '../config/boot'` line (@nesquena)
- NEW #2418 Add `rake db:dump` (`sq:dump`, `ar:dump`) to dump database data to `tmp/<env>_dump.sql`, or to `FILE=`, for postgres, mysql and sqlite. It runs `pg_dump`, `mysqldump` or `sqlite3`, which must be on PATH, with the app's connection and TLS settings; the dump file is readable only by its owner, and a failed dump keeps the earlier one (@achiurizo)
- FIX #2422 `-d activerecord` projects on Active Record 7.1+: `rake ar:create` (`db:create`) creates a missing Postgres or MySQL database instead of printing "already exists" and creating nothing (Active Record now connects lazily, so the task's existence check never failed), and creates the SQLite file it used to leave to the first migration. An existing database is still reported as existing, so `rake db:create db:migrate` can run again. Dropping a database that doesn't exist, SQLite included, succeeds (@nesquena)
- WARN #2422 `rake ar:create`, `ar:drop` and their `:all` forms exit non-zero when a database can't be created or dropped (server down, wrong credentials, no privilege), as Rails does, instead of printing the error and exiting 0; scripts that ignored those errors now stop there
- FIX #2421 `-m rr` projects (`padrino g project -m rr` and `padrino g component -m rr`) load rr in their tests: minitest projects get `require 'rr'` after `config/boot` instead of an `RR::Adapters::MiniTest` include that raised `uninitialized constant RR`; rspec projects get `conf.mock_with :rr` and rr's DSL on `RSpec::Core::ExampleGroup`, so rr's `stub` and `mock` work and an unmet mock fails the example (rr replaces rspec-mocks there, so `double` and `allow` are no longer available; RSpec's own `satisfy` matcher keeps working, and rr's `satisfy` argument matcher is not available); testunit and shoulda projects get the `test-unit-rr` gem and `require 'test/unit/rr'`, since rr 3 has no test-unit integration. Bacon, cucumber and projects without a test component get rr in the Gemfile and a hint on how to set it up, as `-m mocha` does, instead of a broken include (@nesquena)
- FIX #2420 `padrino g component -m rr` on an existing project sets rr up for the project's test component, as `padrino g project -m rr` does: minitest projects get `RR::Adapters::MiniTest` in `test/test_config.rb` instead of `RR::Adapters::TestUnit`, and rspec projects get `require 'rr'` in `spec/spec_helper.rb` (@achiurizo)
- FIX #2419 `-d sequel` projects: a `references` or `belongs_to` field in `padrino g model` and `padrino g migration` generates an indexed foreign key (`user:references` becomes `foreign_key :user_id, :users, index: true`, or `add_foreign_key` and `drop_foreign_key` in a migration) instead of a `References` column that fails `rake sq:migrate`. The foreign key points at the pluralized table, which must exist first: Postgres and MySQL reject the migration, and SQLite accepts it but then rejects every insert, since Sequel enables foreign keys there. `uniq` makes the reference's index unique, and `polymorphic` adds `<name>_id` and `<name>_type` columns indexed together. A third `index` or `uniq` segment now also applies to any other Sequel column (`slug:string:uniq` becomes `String :slug, index: { unique: true }`); before, Sequel ignored it (@nesquena)
- FIX #2417 `rake sq:create` and `sq:drop` create and drop Postgres and MySQL databases over a Sequel connection instead of running `createdb`, `dropdb` or `mysql`, so they work when the database server runs in a container without those clients installed locally. Postgres connects to the `postgres` database, then `template1`, as `createdb` and `dropdb` do (only `template1` when the database itself is named `postgres`). Projects generated with `-d sequel` pass `test: false` to `Sequel.connect`, so `sq:create` can run before the database exists (models still need the database to load); existing projects should add `test: false` to the `Sequel.connect` calls in `config/database.rb` to create a missing database (#2146) (@achiurizo)

Rakefiles that call them directly need the new arguments (@achiurizo)
- FIX #2416 Projects generated with `-d mongoid` set `Time.zone_default ||= Time.find_zone!('UTC')` in `config/database.rb`, so on Mongoid 9 assigning a String or a Date to a `Time`, `DateTime` or `created_at`-style field, or a Date to a `Date` field (an admin form POST, for example), works instead of raising `NoMethodError: undefined method 'parse' for nil`; Mongoid 9 reads those values in `Time.zone`, which only Rails sets. Existing projects on Mongoid 9 should add that line to `config/database.rb` (use `Time.zone_default`, not `Time.zone =`, which applies only to the thread that boots the app); on Mongoid 8 and older it would change zone-less form times from the server's local zone to UTC unless you name your server's zone. In new projects, values read from Time fields are `ActiveSupport::TimeWithZone` in UTC instead of the server's local time (@nesquena)
- FIX #2414 `padrino g model` in a Mongoid project writes a Mongoid type for the field kinds the SQL generators take, so the model loads instead of raising NameError (such as `uninitialized constant Post::Text`): `text` and `uuid` become String, `bigint` Integer, `decimal` BigDecimal, `datetime` and `timestamp` Time, `binary` BSON::Binary, `json` Object and `object_id` BSON::ObjectId, and a `references` or `belongs_to` field becomes `belongs_to` (with `polymorphic: true` for `:polymorphic`). Other kinds, such as `string`, `boolean` or a class name of your own, are written as before (@nesquena)
